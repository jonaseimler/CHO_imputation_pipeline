# Imputation of sensor blackouts in CHO-K1 cultivation data

Code accompanying the manuscript *[title of the revised manuscript]* ([journal], [year], DOI: [to be added]).

The repository reproduces the full analysis: preprocessing of the inline sensor data, sensor clustering, simulation of contiguous sensor blackouts, Bayesian hyperparameter optimization, imputation with six methods (linear and PCHIP interpolation with and without smoothing, FLk-NN, iterative Hankel/SSA completion), the statistical evaluation, the application to real outages, the downstream evaluation (PLS soft sensor, PCA-based monitoring) and the tables and figures of the manuscript.

## Data

**Source dataset.** The cultivation data are publicly available on Zenodo (Uhlendorff et al., CC BY 4.0): <https://doi.org/10.5281/zenodo.20829177>. The dataset contains 12 experiments (`EXP001_batch.xlsx` … `EXP009_batch.xlsx`, `EXP010_fed-batch.xlsx` … `EXP012_fed-batch.xlsx`), each run in two parallel reactors (R01, R02), i.e. 24 cultivations. **This study uses only the seven batch experiments EXP001–EXP007 (14 cultivations).** EXP008–EXP012 are not used.

**Input files of this repository.** The pipeline reads `data/raw/EXP001_input.xlsx` … `EXP007_input.xlsx`, which are included in the repository. Each file contains the sheets used in the study:

| Sheet in `EXP00X_input.xlsx` | Sheet in Zenodo `EXP00X_batch.xlsx` | Content |
|---|---|---|
| `R01_CO2`, `R02_CO2` | `R0X_inline_CO2` | Dissolved CO2 |
| `R01_TCD`, `R02_TCD` | `R0X_inline_Turbidity` | Turbidity (transmission, reflection) |
| `R01_VCD`, `R02_VCD` | `R0X_inline_Permittivity` | Dielectric spectroscopy (permittivity, conductivity, Cole parameters, 17-frequency capacitance spectrum) |
| `R01_offline`, `R02_offline` | `R0X_offline_CellAnalysis` | Offline cell counts (viable cell density) |

The measurement values are identical to the Zenodo files, with one exception: in EXP006 the permittivity-module data inside the outages (≈113–115 h, ≈127–144 h and ≈180–192 h) were restored from an ArcAir log file. In the version used in this study the restored data start 72–86 min after outage onset (the preceding interval is interpolated during preprocessing), whereas the Zenodo version is continuous in these intervals. The input files contain the version used in the study. They additionally contain variables that are not part of the Zenodo dataset but are used in the analysis: the absolute timestamps (`Date`), the temperature of each sensor module (`Temperature(°C)`), `Cell Density(pF/cm)` and `TCD(AU)`. Column names follow the instrument export (e.g. `Conductivity(mS/cm)` instead of `Conductivity (mS/cm)`, `Live Cell Conc. Mean` instead of `VCD Mean (cells/mL)`).

**Stored temperature outlier flags.** For EXP001–EXP004 the outlier flags of the module temperatures (`Temperature(°C)`) used in the study were produced with an earlier detector setting that was not recorded. To reproduce the study exactly, these flags are stored in `data/raw/temperature_outlier_flags.csv` (experiment, sheet, timestamp of each flagged sample) and `gap_outlier_detect.py` applies them instead of the computed temperature flags. All other flags, and all flags of EXP005–EXP007, are computed by the script with the settings in `ProcessingConfig`. The column `outlier_score__Temperature(°C)` still holds the score of the current setting; only the flags are used by later steps.

All other files in `data/` are generated by the pipeline. Paths are defined in [`paths.py`](paths.py).

## Pipeline

Run the scripts from the repository root in the order below. Each step reads the output of the previous steps.

| Step | Script | Output | Notes |
|---|---|---|---|
| 1 | `gap_outlier_detect.py` | `data/flagged/EXP00X_FLAGGED.xlsx` | Outlier and gap flags (rolling median + MAD); stored temperature flags for EXP001–004 |
| 2 | `gap_length_detection.py` | console | Durations of the real outages (bounds for the gap simulation) |
| 3 | `simulate_gaps.py` | `data/simulated/`, `results/gap_masks/tuning_gaps_seed42.csv` | Cleaning; tuning gaps for 1–4 blackouts, seed 42 |
| 4 | `correlation_matrix.py`, `cluster_columns.py` | `results/clustering/` | Hierarchical clustering into 4 sensor clusters |
| 5 | `optimize_flknn.py`, `optimize_hankel.py` | `results/optimization/` | Optuna (TPE, 50 trials) on EXP007 only; objective NRMSE + NDTW |
| 6 | `simulate_gaps_multiseed.py` | `data/simulated_multiseed/`, `results/gap_masks/test_gaps_multiseed.csv` | Test gaps on EXP001/002/004, 10 seeds, two placement designs |
| 7 | `run_imputation_multiseed.py` | `results/imputed_multiseed/` | All methods × scenarios; gap values stored as `.npz` |
| 8 | `evaluate_multiseed.py records`, then `evaluate_multiseed.py stats` | `results/evaluation_multiseed/` | Per-gap metrics, hierarchical bootstrap, tables |
| 9 | `real_outages.py` | `results/real_outages/` | Methods applied to the real outages in EXP003/005/006 |
| 10 | `downstream_evaluation.py records`, `stats`, `real` | `results/evaluation_downstream/` | PLS soft sensor (VCD) and PCA-MSPC |
| 11 | `revision_diagnostics.py` | `results/evaluation_multiseed/diagnostics/` | FLk-NN decomposition, Hankel and CO2 periodicity |
| 12 | `paper_outputs.py` | `results/paper/` | Tables and figures of the manuscript; key numbers of the text (`key_numbers.md`) |

Shared modules: `impute_methods.py` (imputation methods), `metrics.py` and `evaluation_metrics.py` (metrics), `revision_config.py` (methods, clusters, loading of the optimized hyperparameters from the Optuna logs), `paths.py` (paths).

Notes:

- **Cluster numbering.** `results/clustering/cluster_assignments.csv` and the optimization logs use internal cluster IDs. They map to the manuscript as CSV 1 → Cluster 4 (temperatures), CSV 2 → Cluster 1 (capacitance/turbidity, 23 variables), CSV 3 → Cluster 2 (conductivity, fc), CSV 4 → Cluster 3 (alpha, CO2) (`PAPER_CLUSTER` in `revision_config.py`). Tables and figures use the manuscript numbering.
- **Faulty channels.** In EXP001 R02 and EXP002 R02 the capacitance spectrum, DeltaEps, fc and alpha were not recorded. These channels are excluded from the evaluation and are not used as inputs of FLk-NN and Hankel (`is_excluded_sensor` in `evaluation_metrics.py`).

### Runtime and memory

- Step 5: the Hankel optimization took about 40 h on 4 cores (16 GB RAM).
- Step 7: baselines and FLk-NN can run in parallel (`--jobs 3`). Run Hankel with `--jobs 1`: for 15-h gaps in the 23-variable cluster, the block-Hankel matrix needs several GB.
- Steps 7–10 can be resumed; existing results are skipped.

## Included results

To make the reported numbers verifiable without re-running the expensive steps, the repository contains:

- `results/optimization/`: complete Optuna logs (all trials) and the selected hyperparameters for FLk-NN and Hankel (16 gap-count × cluster combinations each). The parameters used for imputation are read directly from these logs.
- `results/clustering/`: correlation matrix and cluster assignment.
- `results/gap_masks/`: positions of all simulated gaps and the simulation settings, including seeds. `tuning_gaps_seed42.csv` holds the tuning gaps (EXP007 is the tuning experiment); `test_gaps_multiseed.csv` holds the test gaps (copy of `data/simulated_multiseed/gap_positions.csv`).
- `results/paper/tables/`: Table 1 and the supplementary tables S1–S16 as CSV.
- `results/paper/repository/`: additional result tables not printed in the manuscript (all pairwise comparisons, medians of all methods).

## Reproducibility

- Gap simulation: tuning gaps use `random.Random(42)`; test gaps use `numpy.random.default_rng([seed, n_gaps, design, experiment])` with seeds 1–10.
- Optuna: Hankel uses `TPESampler(seed=42)` with 4 parallel workers; FLk-NN uses the default (unseeded) TPE sampler on all CPU cores. Repeated optimization can therefore yield different trial sequences and selected parameters. The logs of the runs used in the manuscript are included, and all later steps read the parameters from them.
- FLk-NN candidate sampling: `random_state=42`. Hankel randomized SVD: seed `42 + iteration`.
- Bootstrap: fixed seed (`BOOT_SEED` in `evaluate_multiseed.py`).
